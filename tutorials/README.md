# 动手搞懂 evolver.py：一套不背名词的实战教程

如果你刚打开这个仓库，看到满屏的 **GEP**、**Gene**、**Capsule**、**Autopoiesis**、**Solidify**、**Episode**、**Placebo Ablation**，头皮发麻是很正常的。

记住一个词叫什么，和搞清楚它到底在干什么，完全是两码事。你可以把一只鸟在全世界所有语言里的名字背得滚瓜烂熟，但背完之后，你对这只鸟怎么飞、吃什么虫子依然一无所知。

这套教程只有一条规矩：**不拿术语解释术语，不从理论推导理论。**

每一讲我们都从一个具体的工程麻烦开始，把高大上的名字扒掉，看硬盘上到底多了哪个文件、进程到底跑了哪条命令、哪道门拦住了哪次乱改。每一讲末尾都有几条 10 秒钟能跑完的命令——别光听我说，你自己敲一下，亲眼看看机器是怎么转的。

## 🗺️ 课程路线图

建议按顺序读，每一讲都在回答前人踩过的一个真坑：

1. **[第一讲：扒掉术语外衣，这台机器到底在干嘛？](./01-what-it-really-does.md)**  
   为什么你的 AI 编程助手今天修好的 bug，下周换个对话又犯一模一样的错？把 Gene、Capsule、Signal、Solidify 还原成你每天都在用的四样东西。
2. **[第二讲：亲手转一圈齿轮——从报警到入库的七步](./02-one-cycle-by-hand.md)**  
   不调任何外部大模型，我们自己当一回改代码的工人，跟着引擎走完一次单周期。看看七阶段流水线往字典里塞了什么，又为什么非要在 `git commit` 前面加一道 `solidify` 安检门。
3. **[第三讲：蜂群接管——为什么引擎自己不调大模型？](./03-swarm-and-host-takeover.md)**  
   后台全自动改代码为什么容易变成灾难？看看 `evolver.py` 怎么反过来用 MCP 协议接管你的 Cursor 或 Claude Code：引擎当大脑和裁判，宿主当手术刀，人握着随时拉闸的刹车线（HITL 与 HOTL）。
4. **[第四讲：别自己骗自己——假说门、预期落差与跨轮重注视](./04-not-fooling-yourself.md)**  
   最容易骗到的人就是你自己。怎么防止 AI 靠瞎猜撞大运过测试？改代码前先押注（`expected_outcome`）、报错被截断时按问题调取原件（`episode_inspect`）、上下文快满时先写草稿（`WORKING_SESSION.md`），以及最关键的护栏：宿主说的只能当线索，引擎亲眼测出的才算证据。
5. **[第五讲：怎么证明它真的变强了？（冻结包、密封题与消融盲测）](./05-measuring-real-progress.md)**  
   搭一座竹子做的指挥塔，飞机是不会降落的。怎么区分“看着像在进化”和“真正在变强”？看懂仓外冻结考卷、密封考题防偷看（`val_seal`）、等长废话占位对照（`--placebo`），以及为什么样本不到 30 道题就不准宣布成功。

## ⚡ 0 号实验：先用 30 秒看它转起来

在读第一讲之前，先在仓库根目录下敲这两条命令，亲眼看一次闭环：

```bash
# 1. 检查当前环境与工作区健康状态
uv run evolver check

# 2. 不连任何外部 API，在临时沙箱里跑通一次完整的 MCP 蜂群闭环
uv run python examples/swarm-quickstart/demo_swarm_loop.py
```

看到终端里一步步打印出 `swarm_boot`、`swarm_tick`、`swarm_distill`、`swarm_solidify` 了吗？不用急着看懂每一行输出。翻开 **[第一讲](./01-what-it-really-does.md)**，我们把它拆开看。
